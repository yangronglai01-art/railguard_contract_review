# RailGuard 基础模型质量优化报告（Prompt v3）

更新时间：2026-09-18

## 1. 优化目标

本阶段只优化基础模型审核质量，不执行监督微调，也不部署微调模型。

开发阶段验收门槛：

- 精确率不低于70%
- 召回率不低于85%
- F1不低于75%
- 21例开发基准的误报不超过15项
- 大模型输出协议错误为0

`data/evaluation/contract-review-v1.json` 已用于提示词开发，因此只能作为开发基准，不能作为最终泛化指标。未来最终指标必须使用尚未参与提示词、规则或训练的held-out测试集。

## 2. 原始结果

### 确定性规则基线

- TP=13，FP=2，FN=13
- 精确率86.67%
- 召回率50.00%
- F1=63.42%

### DeepSeek基础模型 Prompt v2

- TP=26，FP=77，FN=0
- 精确率25.24%
- 召回率100.00%
- F1=40.31%
- 风险等级准确率80.77%

结论：工程证据链正常，主要问题是模型把最佳实践和细节增强建议误判为合同风险。

## 3. 误报归因

77项误报按类别分布：

| 候选类型 | 风险类别 | 误报数量 |
|---|---|---:|
| 已有条款风险 | 违约责任 | 19 |
| 已有条款风险 | 数据安全 | 17 |
| 已有条款风险 | 运维服务 | 16 |
| 已有条款风险 | 知识产权 | 8 |
| 已有条款风险 | 验收 | 7 |
| 已有条款风险 | 付款 | 6 |
| 缺失条款 | 运维服务 | 2 |
| 缺失条款 | 数据安全 | 1 |
| 缺失条款 | 付款 | 1 |

前三类合计52项，占全部误报约67.5%。共同原因是Prompt v2要求识别“内容不充分”，但没有定义最低合格线，导致模型持续追究违约金公式、事件报告时限、分包责任、故障等级和移交清单等理想细节。

## 4. 本次优化

### Prompt v3

- 改为精确率优先，存在疑问时不报告。
- 明确六类风险的最低合格线。
- 禁止把最佳实践、可选增强项或缺少量化细节单独作为风险。
- 每个Agent的每个分类最多输出一项最重要风险。
- 明确高、中、低风险等级边界。

### Precision Guardrail v1

- 在模型输出通过原有协议校验后执行，不能掩盖越权分类、伪造条款ID或非法引用。
- 只保留明确全额或高比例预付、自动验收、必要条款完全缺失，以及核心事项整体留待协商的候选项。
- 对达到最低保护线的合同条款过滤最佳实践型误报。
- 根据数据处理适用性判断纯机械设备采购是否需要数据安全条款。
- 对运维服务缺失和局部响应时限缺口分别校准为中、低风险。

- 精确率100.00%
- 召回率100.00%
- F1=100.00%
- 风险等级准确率100.00%

该结果证明护栏能够处理已观察到的77项误报，但由于21例开发基准已参与规则设计，不能作为最终泛化成绩，也不能替代真实模型重新推理。

### 独立挑战测试

新增高端装备制造场景挑战测试，覆盖：

- 90%签约预付款
- 逾期未反馈默认验收
- 知识产权、责任、运维和数据保护后续另议
- 最终验收后支付全部款项的安全表达
- 已有基础保护但缺少理想细节
- 纯机械设备采购的数据安全不适用性
- 远程设备运维的数据安全适用性

挑战测试和开发边界测试共18项，全部通过。

## 6. 尚未完成的真实模型验收

2026-09-18尝试运行Prompt v3的8例真实模型小评测，DeepSeek接口在第1例返回HTTP 402 `Insufficient Balance`，没有产生可用评测结果，也没有覆盖正式报告。

余额恢复后应先运行8例小评测，再运行21例完整开发评测。只有真实评测同时达到预设门槛，才能把本阶段标记为最终达标并进入微调准备。

## 7. 微调准入条件

开始微调前必须满足：

1. Prompt v3真实21例开发评测达到精确率70%、召回率85%、F1 75%。
2. 协议错误为0，并检查被护栏过滤的候选项日志或抽样结果。
3. 独立构造SFT训练集和验证集，不复制21例开发基准。
4. 冻结新的held-out测试集，且在最终对照评测前不得查看其标签和结果。
