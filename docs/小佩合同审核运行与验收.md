# 小佩合同审核运行与验收

本轮范围：本地单机模拟业务迁移。源码保留RailGuard技术名、采购方立场、三Agent与人工复核机制。合成规则版本petkit-procurement-demo-v1；场景提示词版本contract-risk-v3-petkit-1。所有规则为开发用合成要求，不是小佩真实制度或法律意见。

## 已验证

1. 新profile、独立语料和运行目录；隔离演示入口不读取私有.env，不继承宿主模型密钥与旧数据库路径。
2. 六类合成规则和五个开发合同样本：风险、保护充分、数据事项待协商、否定付款、标准SaaS订阅许可。
3. 小佩合同无论是否识别风险，都等待人工决定；保留原场景行为。
4. 新增场景回归覆盖DOCX上传、原文位置、风险类别、来源匹配、制度版本、人审、重启恢复、混合语料拒绝，以及模型工厂的profile传递。模型工厂测试为替身，不能记作真实模型测试。
5. 真实本机HTTP冒烟：独立API进程接收DOCX，返回六类风险、全部来源匹配；Streamlit AppTest渲染小佩场景；停止并重启API，仍可读取同一任务并人工退回。本轮拥有的API进程全部停止。

冒烟证据见verification/petkit-migration-smoke.json。原仓库完整离线回归232项全部通过（新增小佩场景13项），11.09秒，只有1条既有anyio弃用提示；Ruff与git diff --check通过。完整JUnit为verification/petkit-migration-regression.xml。副本因缺Git元数据产生的两项原测试失败，在原仓库已全部通过。

## 运行

仓库根目录：

```powershell
.\.venv\Scripts\python.exe -m railguard.petkit_demo serve
$env:RAILGUARD_API_BASE_URL = 'http://127.0.0.1:18020'
.\.venv\Scripts\python.exe -m streamlit run src/railguard/ui/app.py --server.address 127.0.0.1 --server.port 18520
```

后端与前端分别运行于两个终端。后端仅本机访问；不要把本地演示暴露为多人服务。停止用Ctrl+C。重启使用同一个--data-dir可恢复原任务；不能删除checkpoint或重新构建运行目录。

生成上传样本：`python -m railguard.petkit_demo samples`。重复生成不覆盖文件，使用新的--data-dir。样本内容是测试输入，不能作为正式合同模板使用。

不受旧.env影响的完整回归：

```powershell
.\.venv\Scripts\python.exe scripts/test_petkit_offline.py
.\.venv\Scripts\python.exe -m ruff check src tests scripts
```

测试脚本仅在自身进程禁用.env和配置环境变量，临时数据库在新建的系统临时目录。原仓库执行可获得真实Git元数据；没有Git信息的源码副本中，原有两项追溯断言会失败，不应篡改成通过。

## 未验收边界

- Mock规则有限，不能证明复杂条款语义、法务准确率或真实模型效果；五个样本是开发用例，不是独立盲测。
- 引用校验验证来源ID和类别一致，不证明规则的法律效力或所有结论被证据蕴含。
- 续做已完成本地个人身份、合同授权、后端审核人及元数据审计；企业SSO仍未做，见《小佩个人权限与容器运行.md》。
- 真实RAG、统一底座、真实模型费用与准确率、生产数据迁移均未做；旧DeepSeek分支是Responses协议，后续接底座应选择经验证的Chat Completions分支。
- 续做已完成专用compose.petkit-local.yaml的镜像构建、容器权限与持久重启验收。通用Compose未实跑，仍无生产容量、长期负载或多实例恢复结论。
- OEM、经销、消费者与跨境专项未适配。旧评测/SFT资产仍为旧口径，没有声称微调项目已立项。
