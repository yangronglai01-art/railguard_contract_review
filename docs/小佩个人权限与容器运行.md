# 小佩个人权限与容器运行

续做日期：2026-10-21。范围为本地单实例合成业务验证，模型与知识库保持Mock。企业SSO、真实数据、底座/RAG联调、生产上线均不在本次已完成范围。

## 权限边界

| 角色 | 可以执行 | 无权执行 |
| --- | --- | --- |
| submitter | 上传自己的合同、启动审核、读取自己的合同/任务、授予或撤销指定审核人的合同权限 | 读取其他提交人合同、替审核人批准 |
| reviewer | 读取被逐合同授权的正文和任务、作出人工决定 | 上传合同、自行取得合同权限、读取未获授权内容 |
| auditor | 读取操作审计及聚合监控 | 读取合同正文和审核详情、作审核决定 |

审核人由后端认证身份写入，忽略请求中伪造的reviewer值。授权、角色、令牌有效期在读取结果前再次检查；审核决定在取得任务锁并读取checkpoint后、恢复图之前重新授权。轮换、撤销、到期、停用均使旧令牌不可使用；角色变更和重新启用还需重新授权。任务列表按授权过滤，默认100条，limit最大200，支持offset。

没有个人账号的免登录库继续可演示；一旦库中存在个人账号，不能再用免登录入口打开。旧合同和checkpoint不会自动挂到新账号名下，避免错误分配敏感资料。原数据不删除，推荐新建独立目录验证权限。

## 本机启动与操作

```powershell
# 原仓库根目录，选择新的权限演示目录
.\.venv\Scripts\python.exe -m railguard.identities provision --data-dir data/runtime/petkit-access
.\.venv\Scripts\python.exe -m railguard.petkit_demo serve-secure --data-dir data/runtime/petkit-access

# 另一个终端启动前端
$env:RAILGUARD_API_BASE_URL = 'http://127.0.0.1:18020'
.\.venv\Scripts\python.exe -m streamlit run src/railguard/ui/app.py --server.address 127.0.0.1 --server.port 18520
```

provision只允许初始化尚无个人账号的库，重复运行不轮换已有凭据。四个合成账号为buyer-01、buyer-02、legal-01、auditor-01；个人凭据在所选目录credentials.json，默认8小时到期，数据库只保存SHA-256指纹和有效期。终端不打印令牌。Unix私有文件模式0600；Windows仍以所在目录的OS访问权限为准，不能将chmod当成Windows ACL验收。

页面内登录后，提交人上传并启动审核，在“审核人授权”中授予legal-01。审核人以自己的凭据登录，读取我的审核任务，打开授权任务再决定。每个浏览器会话持有独立HTTP客户端，退出和身份失效清除合同快照，不使用全局缓存共享个人凭据。API还提供：

- GET /security/me：当前身份。
- PUT/DELETE /contracts/{id}/reviewers/{subject}：仅合同提交人授权/撤权。
- GET /security/audit：仅审计员，最多500条元数据。
- GET /reviews?limit=100&offset=0：当前可见任务。

本地操作员维护身份（不是开放的管理API）：

```powershell
.\.venv\Scripts\python.exe -m railguard.identities status --data-dir data/runtime/petkit-access
.\.venv\Scripts\python.exe -m railguard.identities rotate --data-dir data/runtime/petkit-access --subject legal-01
.\.venv\Scripts\python.exe -m railguard.identities revoke --data-dir data/runtime/petkit-access --subject legal-01
.\.venv\Scripts\python.exe -m railguard.identities disable --data-dir data/runtime/petkit-access --subject legal-01
```

轮换后从私有文件读取新凭据，其他人的凭据不变。若磁盘写入失败导致轮换文件未更新，旧令牌已失效，修复文件系统后重新rotate；不要重新provision或重建业务库。

## 审计及一致性边界

上传合同、写入所有者和上传审计在同一个SQLite事务中完成；审计写入失败整体回滚。授权/撤权与对应目标账号记录也在同一事务。审计字段仅包含时间、账号、动作、资源ID、授权目标和结果，不包含合同正文、原始文件名、提示词、回复或原始令牌。

审核启动、决定先留意图，再执行LangGraph，再记录结果；业务SQLite与checkpoint是两个文件，没有跨文件事务。图已提交而最终审计写入失败时，可能返回503但决定已经持久化，此时应先重新读取任务，不能盲目重试。意图保留用于排查，不能声称整个审核动作与审计全程原子提交。进程内任务锁不等于多实例分布式锁。

元数据审计不是防篡改审计链；OS管理员仍能访问本地库。真实企业身份、数据保留、加密和多实例方案需要单独验收。

## Docker隔离配置

使用compose.petkit-local.yaml和configs/petkit-local.env，不加载旧私有.env。该配置固定Mock、个人权限及独立卷，API和UI只映射到宿主127.0.0.1的动态端口。

```powershell
docker compose --env-file configs/petkit-local.env -f compose.petkit-local.yaml build api
docker compose --env-file configs/petkit-local.env -f compose.petkit-local.yaml up -d --no-build
docker compose --env-file configs/petkit-local.env -f compose.petkit-local.yaml exec api python -m railguard.identities provision --data-dir /app/data/runtime/petkit
docker compose --env-file configs/petkit-local.env -f compose.petkit-local.yaml port api 8000
docker compose --env-file configs/petkit-local.env -f compose.petkit-local.yaml port ui 8501
```

个人凭据在容器私有卷中；以本地可信操作员方式读取对应账号凭据，不在共享终端或日志中显示整份文件。重启保留卷即可保留账号、授权、合同、审计与checkpoint。日常停止用down，保留业务卷；只有独立验收脚本会清理它自己随机生成的项目及其卷。

镜像固定Python 3.11基础镜像摘要与81项Linux运行依赖，API/UI均以UID10001运行。requirements.lock为运行版本锁，非带哈希的供应链校验；后续升级需重新测试。通用compose.yaml只做配置兼容，已验收范围以专用petkit-local配置的报告为准。
